# Tess Tregellas — personal website

This is the personal website of **Tess Tregellas**, a NYC stand-up comedian, content creator and self-described hopeless romantic. Tess owns the site and is the person you'll usually be talking to.

## Who you're working with

Tess is **not a developer**. She wants to update her site by describing what she wants in plain English.

- Explain things in plain language. Skip jargon, and if a technical word is unavoidable, say what it means in a few words.
- Don't ask her to run terminal commands or edit code herself. Do the work for her.
- After each change, **show her the change in the preview** (browser pane at http://localhost:3000) and describe it briefly.
- **Never publish without asking.** Publishing means `git commit` + `git push` to `main`, and that makes the change go live on the real site within a couple of minutes. Before each push, tell her in a sentence or two what's changing and ask "Ready to make this live?"
- Keep each publish to one clear change so it's easy to undo.

## How the site works

- **Framework:** Next.js 16 (App Router) + React 19 + Tailwind CSS v4, written in TypeScript.
- **Hosting:** Vercel, linked to the GitHub repo `tesstreg-code-queen/my-website`. Every push to `main` deploys automatically. There's no separate deploy step.
- **Domain:** tesstregellas.com
- **Newsletter:** "The Hopeless Romantic Report" on Beehiiv. The signup form posts to Beehiiv's API from `app/actions.ts`.

## Style

The look is playful and romantic. It uses chunky ink outlines, hard drop shadows (`shadow-pop`), slight tilts (`-rotate-1`, `rotate-2`), hearts, and a script font for little asides. The copy is funny, flirty and self-deprecating. Match that voice when writing new text, and offer Tess a couple of options when it's her words going on the page.

## Running it

- **Preview:** start the `website` server from `.claude/launch.json` (that runs `npm run dev`), then open http://localhost:3000.
- If `node_modules` is missing (on a fresh computer, for example), run `npm install` first.
- Before publishing a bigger change, run `npm run build` to catch errors. If the build fails, the site won't deploy, and the previous version stays live.

## Newsletter keys

The signup form needs `BEEHIIV_API_KEY` and `BEEHIIV_PUBLICATION_ID`. They're already set in Vercel for the live site. To test signups locally, they go in `.env.local` (git-ignored, never committed). Have Tess paste the keys into that file herself. Never ask her to type them into the chat, and never commit them. Without the keys, the local form shows "Something broke on our end", which is expected.

## Publishing (git)

- Work directly on `main`. Tess doesn't need branches or pull requests.
- The first push from a new computer may ask her to sign in to GitHub. Let her do the sign-in herself.
- If git asks for a name/email for commits, ask Tess what she'd like to use.
- To undo a published change, use `git revert` on that commit and push. Vercel also has an "Instant Rollback" button on the project's Deployments page.
